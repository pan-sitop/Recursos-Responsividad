El Problema del Mundo Real 🌍

¿Qué es el Diseño Responsivo?

Es la técnica que permite que una única base de código (HTML/CSS) adapte su estructura, tamaño y comportamiento al dispositivo en el que se está viendo.

Antes, las empresas hacían dos sitios web: www.sitio.com y m.sitio.com. Era una pesadilla de mantenimiento.

La Etiqueta Obligatoria (Viewport)

Sin esta etiqueta, el celular intentará renderizar la página de escritorio alejada (zoom out), haciendo el texto ilegible.

Regla de oro: Si tu página se ve "chiquita" en el celular en lugar de reordenarse, olvidaste el Viewport.

Las Dos Filosofías 🎭

Desktop-First vs Mobile-First

Desktop-First (De Mayor a Menor)

  • Se diseña primero para la PC.
  • Se usa max-width para "destruir" o apilar el diseño en pantallas pequeñas.
  • Ideal para: Dashboards o paneles administrativos complejos.

Mobile-First (De Menor a Mayor)

  • Se diseña primero para el celular. El CSS base es muy ligero.
  • Se usa min-width para "construir" columnas a medida que la pantalla crece.
  • Ideal para: El 90% de la web. Google penaliza en el SEO a las páginas que no priorizan móviles.

La Sintaxis Básica 🎙️

Preguntándole al Navegador.

¿Qué es una Media Query?

Es un bloque condicional (como un if en programación). Si la pantalla cumple la condición, se aplica el CSS interior.


/* CSS base (ej. Escritorio) */
.tarjeta { width: 50%; }

@media (max-width: 768px) {
    /* SOLO se activa si la pantalla mide 768px o menos */
    .tarjeta { 
        width: 100%; 
    }
}

La Cascada (¡El error mortal!) ⚠️

El CSS se lee de arriba hacia abajo. Tu Media Query DEBE ir debajo de la regla original para poder sobreescribirla.

MAL ❌


@media (max-width: 768px) {
    h1 { font-size: 20px; }
}

/* Esta regla aplasta a la Media Query */
h1 { font-size: 50px; }

BIEN ✅


h1 { font-size: 50px; }

@media (max-width: 768px) {
    /* Gana por estar más abajo en la cascada */
    h1 { font-size: 20px; } 
}

Puntos de Ruptura (Breakpoints) 🚧

El mito de los dispositivos

No intenten crear un CSS para el "iPhone 15" y otro para el "Samsung S24".

La regla real: Pon un breakpoint exactamente en los píxeles donde TU diseño se rompa o deje de leerse bien.

Operadores Lógicos (and / or)

Podemos ser muy específicos limitando rangos con la palabra and, o usando la coma , que funciona como un operador "OR".


/* AND: Rango estricto (Solo Tablets) */
@media (min-width: 481px) and (max-width: 768px) {
    .grid { grid-template-columns: 1fr 1fr; }
}

/* OR (coma): Si es móvil pequeño O si es muy ancho */
@media (max-width: 320px), (min-width: 1500px) {
    .alerta { display: block; }
}

Nivel Dios 🚀

Más allá del ancho de la pantalla.

1. Orientación (Rotar el Celular)

A veces necesitamos arreglar el diseño si el usuario voltea su dispositivo horizontalmente.


@media (orientation: landscape) {
    /* Se aplica si el ancho es mayor que el alto */
    .menu-superior { height: 50px; }
}

@media (orientation: portrait) {
    /* Se aplica si el alto es mayor que el ancho (celular vertical) */
}

2. El Problema del "Hover" 👆

Los celulares NO tienen ratón, por lo tanto, el :hover se queda "pegado" al tocar la pantalla. Podemos evitar estilos hover en móviles así:


/* Solo aplica este hover si el dispositivo TIENE un puntero principal (mouse) */
@media (hover: hover) {
    .boton:hover {
        transform: scale(1.1);
        background-color: blue;
    }
}

3. ¡Modo Oscuro Automático! 🌙

Podemos detectar si el usuario tiene su sistema operativo en Modo Oscuro o Claro y reaccionar a ello directamente con CSS.


/* Si el celular o PC del usuario está en modo oscuro... */
@media (prefers-color-scheme: dark) {
    body {
        background-color: #121212;
        color: #ffffff;
    }
}

¡Esto les dará puntos extra en cualquier proyecto final!
